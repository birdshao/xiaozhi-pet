# 架构决策记录（ADR）

日期：2026-10-25（ADR-009 起为 2026-11-02 按实物硬件新增）。此处记录已确定方向、限制条件和需要用实测推翻的假设。

## ADR-001：采用小智开源固件 + 自建 Python 语音服务 + 独立儿童业务

**状态：已采纳**

**背景**：需要儿童 AI 对话、虚拟宠物、学习/绘本、未来升级和深度画面控制。官方云 + MCP 无法保证每轮 ASR/回复必经自定义审核，也不保证每个动作/翻页的确定性。

**决定**：
- 保留小智固件的音频、设备网络、OTA 基础。
- 用开源自建语音服务连接 ASR、LLM、TTS（可用外部 API；不强制本地运行所有模型）。
- 单独构建 Pet/Learning Service，拥有状态与数据。
- 官方云仅用作硬件/语音基线对照，不纳入核心业务运行依赖。

**结果**：增加部署与维护任务；获得更完整的对话控制、输出审核和模型选择能力。未来可以替换某个语音服务，宠物数据和业务接口不迁移。

## ADR-002：宠物状态和场景在设备端确定性执行

**状态：已采纳**

ESP32 持有即时状态、输入事件及离线最小状态。Python 保存长期档案、学习记录及同步快照。跨端事件带 ID、版本号，重复传送不会重复奖励。LLM 只提出有限的语义意图，不直接修改数值或屏幕缓冲。

## ADR-003：显示独立于小智默认聊天 UI

**状态：已采纳**

在微雪板卡适配层扩展 PetDisplay/SceneComposer/RefreshScheduler。沿用底层 SPI 和可复用 LVGL 能力，但不依赖默认聊天气泡布局。墨水屏只输出离散状态画面；P1 通过实际 refresh/残影/内存试验确定局刷策略。

重要：目前板卡适配实现 `lvgl_flush_cb` 在刷新时清屏并转换区域，`EPD_DisplayPart()` 写入 48KB 帧缓冲；“存在局刷方法”并不保证真正的最小区域物理更新。

## ADR-004：音频必须由单一协调器仲裁

**状态：已采纳**

本地故事、提示音和云端/自建 TTS 不可各自写入编解码器。使用统一 AudioCoordinator 管理播放优先级、可打断点、恢复策略及错误状态。离线故事播放需新增模块，不能假设小智原版 SD 卡内容可直接播放。

## ADR-005：上游采用冻结基线 + 轻量适配

**状态：已采纳**

定期审查上游 release，但不自动把每次提交部署到儿童设备。保留改动最小的 Board/App/Display/Audio 适配层，业务逻辑做独立组件；所有上游升级经过协议、真机、OTA 回滚测试。服务端只在客户端通信协议、认证、事件接口变更等需要时更新，不要求固件和语音端版本强制同步。

## ADR-006：儿童安全执行为基础能力，不只靠角色提示词

**状态：已采纳**

开放式回复必须可以在输出 TTS 前执行审核；未完成此能力时只能进行成人陪同测试。内容包有审批标志，家长控制本地离线可执行。避免存储原始儿童音频及敏感身份信息。

**修订（2026-11-08，用户决定，见 ADR-015）**：开放问答**不做内容审核**，既不接外部审核服务，也不让模型输出再审一遍。“输出 TTS 前执行审核”因此改为“输出 TTS 前执行**本地硬规则**”：长度、电话、地址、链接、敏感词，另加角色设定提示词和熔断。“儿童安全不只靠角色提示词”这一条仍然成立，因为硬规则、整句缓冲、代码开关和熔断都不依赖模型是否听话。其余内容不变。

## ADR-007：接入上游源码的版本管理方式

**状态：待 P0 决策**

候选：外部 checkout + Overlay/Patch，或 Git submodule + 自建独立组件，或直接维护上游 fork。

**选择标准**：能最少修改上游、明确版本锁定、可重复构建、便于合并 release、能在 GitHub Actions 持续验证。P0 对 2 种实际构建路线做原型，再确定，不提前假设固定组织方式。

## ADR-008：不以 MCP 作为关键动作总线

**状态：已采纳**

MCP 只提供非关键模型工具（查故事上下文、读取宠物摘要等）。按键翻页、喂食、成长奖励、音量/家长时限通过本地应用和可靠业务事件 API 执行，不依赖模型是否选择调用工具。

**修订（2026-11-08，用户决定，见 ADR-016）**：在开放问答里，大模型可以通过设备端 MCP 工具 `self.pet.request` **请求**家长允许的那部分板子动作。原则仍然是“执行不依赖模型”：按键路径不变，模型只能提出请求，做不做、奖励多少由板子上的确定性规则决定，说出来的话按设备结果选固定句。“不以 MCP 作为关键动作总线”的意思保持不变：MCP 只是多了一个可选的入口，关键动作并不依赖它。

## ADR-009：拨轮是儿童主操作件，BOOT 只管说话，PWR 改为"哄睡"

**状态：已采纳（2026-11-02，待 V1 真机确认）**

**背景**：资料核对确认板上有三向拨轮（GPIO4/5/6）。旧方案只能用 BOOT 单击/双击/三击，3–5 岁孩子难以掌握；小智原版 PWR 单击直接关机，容易误触。

**决定**：拨轮上/下 = 换一个，按下 = 确认，长按 = 回首页；BOOT 保留小智原语义（说话）；PWR 单击进入可取消的睡觉流程后再关机；家长入口为 BOOT + 拨轮按下 5 s。`PetInputRouter` 的多击映射降为调试模式。

**结果**：所有页面共用一套操作规则；需要选项语音播报弥补不识字。

## ADR-010：电源采用"浅睡眠 + 真关机（画面保留）"两级，作息由 RTC 驱动

**状态：已采纳（2026-11-02，定时开机待 V1-05 验证）**

**背景**：电子纸断电保留画面；PCF85063 闹钟在官方示例中用于关机后定时开机；ESP32-S3 深睡眠只能由 RTC GPIO（0–21）唤醒，姿态和时钟中断不在其中。小智原版 300 s 无操作直接关机。

**决定**：Active → Idle（浅睡眠）→ Nap（浅睡眠、关 Wi-Fi）→ Off（PMIC 关机，显示熟睡画面）；起床时间由 RTC 闹钟开机。由 PowerManager 接管小智 PowerSaveTimer。不依赖深睡眠。

**结果**：宠物有真实作息且省电；若定时开机不可靠，退化为浅睡眠定时器 + 按键开机。

**补充（V3-05，2026-11-04）**：电池 < 20 % 为低电量（≥ 25 % 才恢复），打哈欠提醒找大人充电，并且午睡/关机计时缩短到与夜间相同；< 8 % 为临界（≥ 11 % 才退回低电量），走同一个睡觉流程安全关机（先等宠物事件写入账本、显示熟睡画面、3 s 可取消，然后 PMIC 关机），**不设 RTC 起床闹钟**——在快没电时定时开机只会把电池耗得更空；充好电后按 PWR 开机。临界期间插上电源会取消关机；孩子取消后 60 s 仍为临界会再次进入睡觉流程。插着 USB（充电或已充满）时 PowerManager 永不因无操作关机。PMIC 读数每 2 s 采样，供电来源变化需连续 2 次一致、电量档位变化需连续 3 次一致，防止跳变。

## ADR-011：体感与麦克风互动只在本地做特征判定，不存原始数据

**状态：已采纳**

姿态手势由阈值 + 持续时间判定，只输出离散事件；剧烈摇晃不奖励。麦克风吹气/拍手只算 RMS 包络、只在游戏中开启、与语音会话互斥、不写任何存储。家长可关闭体感。

## ADR-012：宠物个性是固定参数，记忆只来自结构化事件

**状态：已采纳**

性格（好奇/温柔/活泼）由家长设定为参数，驱动审核话术模板和提议权重，模型不能修改。记忆分今日/喜好/成长三层，喜好只能由拨轮选择题事件写入，有容量上限、进账本事务、家长可查看和一键清空。给语音服务只提供最小摘要。不从自由语音文本中抽取个人信息。

**补充（V8，2026-11-07）**：成长记忆里的“游戏完成”（`GAME_COMPLETED`，来源 Device）不限于拨轮答对。体感游戏里做到被要求的轻动作（滚球进洞、迷宫到终点、木头人不动 3 s、按提示翻起）和拨轮选对一样算“答对”，沿用 V4-07 的先例；摇晃、乱动、语音和网络仍然不能写记忆或成长。喜好依旧只来自拨轮选择题。

## ADR-013：电子纸按用途选择刷新模式

**状态：已采纳（参数待 V1-08 实测）**

官方驱动提供局刷、快刷、全刷和 4 灰度。表情/选择高亮/状态栏用 1-bit 分区局刷；场景切换用快刷；每 N 次局刷或拨轮长按做全刷去残影；绘本页、宠物肖像、睡觉画面用 4 灰度全刷。需要扩展小智 `CustomEpdDisplay`（目前只用 1-bit 路径）。

## ADR-014：板上只用原子账本，一次性迁移旧存储，暂不进外发队列

**状态：已采纳（2026-11-04，待硬件验证）**

Waveshare 板从旧 `FreertosPetService`（`kid_pet`）切到 `FreertosAtomicPetService`（`kid_pet_sync` A/B 单块）：宠物状态、V5 记忆、V3-06 家长设置在同一次 NVS 提交里，只有一个写入者。首次启动由 `PetLedgerMigration` 把旧 `kid_pet` 检查点和 `kid_parent/settings` 导入账本：读旧 → 写账本首块 → 逐字节回读 + 独立加载校验 → 才写"已迁移"标记；旧键在标记写入之前只读、不改，标记写入后释放（见下方补充）；每次启动都可重入，任何一步断电都收敛到同一个账本。无法判断的情况（有标记却没有账本、账本内容与旧数据对不上、槽位 1 有未知数据）一律停在原地、不擦除。

板上还没有服务端传输，所以账本以"本地模式"运行：孩子的动作照常提交，但不写入 16 条外发队列（否则离线 16 次喂食后就再也喂不了）。序号游标保持在 1，日后接服务端时按新设备开通。降级刷回旧固件会回到迁移前的旧数据，之后再升级时以账本为准（降级期间的改动丢失）。

**补充（2026-11-04，真机回归）**：16 KiB 的 NVS 放不下两个账本槽位、旧 `kid_pet` 副本，外加改写一个槽位时新旧值同时存在所需的空间（NVS 先写新值再释放旧值，一个账本值约 59 个 32 字节条目）。结果是迁移后只成功提交了一次，之后每次都写不进去。现改为：标记写入且账本可加载之后，释放（擦除）旧 `kid_pet/pet_a`、`kid_pet/pet_b` 和 `kid_parent/settings`，其他键一概不动；失败路径上永远不释放。代价是降级回切换前的固件时，宠物会从头开始。另外，提交连续失败时只重试有限次数（8 次，约 6 s）就放弃这条动作，并记录真实的 NVS 错误码；"回家"存不进去时板子仍回到首页，开机时如果恢复到故事模式却没有可读的书，也会直接回首页。

## ADR-015：开放问答用智谱 GLM，不做内容审核，只留本地护栏

**状态：已采纳（2026-11-08，用户决定；修订 ADR-006 和 V5_V6 方案 §6.5 的 D8；实现见 [SERVER_S6.md](SERVER_S6.md)）**

**背景**：原方案要求开放问答先接一个外部审核提供方，输入、输出各审一遍，没有真实审核时开关一直置灰（D8）。用户评估后认为，外部审核要多花钱、多一次网络往返、多一个能出故障的环节，而模型本身对儿童场景已经比较保守；家长愿意在陪同试用中自己承担剩下的风险。

**决定**：
- 开放问答的模型用智谱 GLM（ChatGLM 接口，默认 `glm-4.7-flash`）。API 密钥由用户写进服务器的 `deploy/providers.env`（`KID_PET_GLM_API_KEY`），不进代码、不进对话、不进日志。
- 不接外部审核服务，模型输出也不再审一遍。
- 保留的护栏都只在本地运行、不花钱：
  1. 本地硬规则，输入、输出各查一遍：长度 ≤ 320 字符；电话、地址、链接/邮箱；敏感词表。输出另外拦截保密/排他的说法、打听个人信息、声称已经做了动作。
  2. 儿童角色设定提示词（V6-04，只用结构化参数拼固定模板）。
  3. 整句缓冲：回复完整拿到、查完才进 TTS，不做流式。
  4. 熔断：10 分钟内连续 3 次模型出错，或一天内输出被硬规则拦 5 次，就自动关闭，只能由家长手动重新打开。
  5. 三道开关：代码开关（等 TTS 出口审计做完才打开）、有密钥、家长打开（打开前看风险说明，并重新输入密码 + TOTP）。
  6. 隐私：每轮只发孩子这一句和最小摘要，不带历史、设备 id 或家长备注；原文不落盘、不进日志。

**取舍**：
- 好处：没有审核费用，少一次往返，响应更快；少一个外部依赖，也就少一个出故障的地方。
- 代价：模型说出不合适内容的风险由本地规则兜底，而本地规则覆盖不了语义层面的问题，比如不当的价值观、错误的常识、措辞微妙的吓人内容。孩子的话会发到智谱的云端。智谱平台自带的过滤（`finish_reason=sensitive`、错误码 1301）照常起作用，但它不在我们的控制之内，也不算我们的审核。
- 缓解：风险说明里写明了这些，建议先在大人陪同下试用；熔断兜住模型异常；家长随时可以一键关闭。

## ADR-016：开放问答里大模型可以请求家长允许的板子动作

**状态：已采纳（2026-11-08，用户决定；修订 ADR-008 和 V5_V6 方案 §6.2 的“只有固定命令匹配器能产出动作”）**

**背景**：#114 让固定命令通过设备端 MCP 工具 `self.pet.request` 到达板子，同时在小智上游的模型函数表里把它隐藏掉。用户认为，孩子说“我们来玩点什么吧”时，团团能直接打开游戏会更聪明。

**决定**：
- 开放问答回合里，PetLearning 把 `self_pet_request` 作为 function calling 工具交给 GLM。`action` 的枚举 = 家长在面板上勾选的子集，默认是讲故事、上一页、下一页、玩游戏、回首页、喂团团、梳毛、唱歌、刷牙、洗手，**不勾睡觉**。
- 模型调用工具后，服务端回一个和固定命令完全相同的 `local_command`（带这个动作的审核确认句），守卫按 #114 的流程调设备，并**按设备结果选固定句**。模型自己的那句话不播报，所以说出来的话不会和设备结果矛盾。
- 板子规则不变：安静时段、低电量、睡觉、家长菜单照样拒绝；语音不写记忆、不发奖励；“喂团团”只打开选菜画面。
- #114 的过滤保留：小智上游的 LLM 函数表在任何模式下都看不到这个工具，点名调用也会被拒绝。只有开放问答打开、走 PetLearning → GLM 这条路时，才按白名单子集提供。

**取舍**：
- 好处：对话更自然，孩子不用记固定说法。
- 代价：模型可能误解孩子的意思而发起动作，比如孩子只是在聊游戏，团团却打开了游戏。
- 缓解：动作都是可撤回的屏幕切换，没有奖励；家长可以只勾选少数几个动作；“睡觉”这种会关机的动作默认不给；模型请求了白名单以外的动作时不执行，并计入熔断。
