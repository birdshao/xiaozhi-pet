# 测试策略、升级兼容和长期维护

文档状态：v0.1｜2026-10-25

## 1. 版本基线与可复现性

对于每次可烧录版本，创建 `version-lock.json`（实现时增加）：

```json
{
  "firmware_upstream_repo": "78/xiaozhi-esp32",
  "firmware_commit": "PIN_AFTER_P0",
  "voice_server_repo": "xinnan-tech/xiaozhi-esp32-server",
  "voice_server_commit": "PIN_AFTER_P3",
  "esp_idf_version": "PIN_AFTER_P0",
  "board": "Waveshare ESP32-S3-ePaper-3.97",
  "business_api_schema": "1.0",
  "pet_state_schema": 1,
  "content_schema": "1.0"
}
```

固定的版本必须是实际成功编译/联调过的 commit，不应把文档撰写当天的上游 `main` 当作未经验证的兼容基线。

记录工具链、分区表、PSRAM 使用、固件大小、设备配置、AI 提供商（不记录明文 API Key）。构建产物应带 git commit、构建日期、变更摘要及可复现的配置哈希。

## 2. 上游变更处理流程

1. **观察**：定期查看小智固件/自建 Python 语音服务端 Release、协议变更、板卡源码和安全修复；安全修复优先评估。
2. **分类**：变更是显示/UI、音频、网络/协议、OTA、Board GPIO、构建工具链、语音配置还是应用功能？
3. **隔离升级**：建立升级分支，先锁定新 commit；不直接在常用儿童设备上 OTA。
4. **静态检查**：依赖、编译、单元测试；检查适配文件 diff；生成分区/镜像体积报告。
5. **协议回归**：老固件+新服务器、新固件+旧服务器、新固件+新服务器，对握手、音频、打断、MCP/意图、断线恢复进行兼容测试。
6. **设备真测**：麦克风、扬声器、电源、屏幕、局刷、SD、IMU、NVS；至少包含联网与断网。
7. **升级/回滚**：测试固件双 OTA 分区、断电恢复、状态迁移和回滚。
8. **发布**：更新版本锁、变更日志与兼容矩阵，先灰度到专用开发板，再手动推广。

原则：小智设备固件更新并不自动要求更新 Python 服务端；仅在兼容性用例失败、协议/认证/消息语义变更或需要新语音功能时才适配。**同样，Python 服务器升级也应独立测试，不必强迫宠物应用升级。**

### 上游主要观察点

| 上游改动 | 重点检查 |
|---|---|
| `application.h/.cc` 和状态机 | 接入事件、音频调用时机、生命周期 |
| `display/` | Display API、LVGL 依赖、锁、主题与字形资源 |
| 微雪 `boards/...` | 引脚、电源、音频和电子纸初始化 |
| OTA/分区/Assets | 双分区、资源冲突、回滚与资产映射 |
| WebSocket/MQTT+UDP 协议 | 握手、音频包版本、心跳、认证、错误码 |
| 语音服务端 ASR/LLM/TTS 插件 | VoiceAdapter hook、安全输出门控、流式逻辑 |
| Python 服务端配置 / 数据库 | 变更可独立于 PetLearning DB |

## 3. P0 硬件基准测试

每项收集 **硬件版本/固件 commit/步骤/实际现象/日志/是否通过**。

| 测试 | 操作 | 通过标准 |
|---|---|---|
| 烧录和启动 | 官方板型编译、flash、monitor | 无启动循环，基线可复现 |
| 音频 | ASR 聊天、扬声器音量、打断 | 录/放音稳定，定位杂音来源 |
| 显示 | 静态全刷、不同局刷窗口、重启 | 正确方向、无越界、不死锁 |
| 输入 | BOOT/PWR 和实物所有键/拨轮 | 可确认实际可用输入，不假设 |
| IMU | 读芯片 ID、静止/拿起/放下 | 记录总线、阈值和误报 |
| SD | 枚举、读写、掉卡、长音频流 | 文件系统稳定，不影响音频 |
| 电池/供电 | USB、电池充放电、休眠唤醒 | 安全、不会异常重启 |
| Flash/PSRAM | 编译 map、空闲堆/碎片和任务栈 | 有可用资源预算 |
| OTA | 实际分区表、尝试测试升级/回滚 | 不损坏存档且可恢复 |

不应在 3–5 岁儿童接触的未封装原型上进行带电池长时间无人看护实验。

## 4. P1 显示专项

测试矩阵：
- 全屏变换（表情↔学习页）、脸部最小变化、状态图标变化；
- 黑白大区域、高对比度线条、文字局刷、重叠区域；
- 重复 10/50/100 次局刷后的残影与全刷恢复；
- SPI BUSY 超时/断线异常与显示重试；
- 同时进行音频收/放时的内存/CPU 与不卡音；
- 从 sleep 恢复后首次刷新与资源重建；
- 并发事件高频输入时刷新队列能合并/丢弃过时 UI 帧。

**测量字段**：触发时间、队列等待、刷新总耗时、峰值堆/PSRAM、音频 underrun、主观残影分级及照片。P1 最终形成 `docs/hardware/EPD_BENCHMARK.md`。

放行准则：在真实设备上画面一致、长期刷新不死锁、音频不明显受影响；如果局刷效果差，允许优先用限频全刷完成 MVP 并明确体验取舍。目标数值由实测确定，**不预先承诺 60 FPS 或毫秒级实体墨水屏反馈**。

## 5. 状态机、音频与同步测试

| 场景 | 检查 |
|---|---|
| 喂食事件重复重传 3 次 | 成长/奖励只增加一次 |
| 断网前执行 20 次本地动作 | 网络恢复后事件不重复不丢 |
| 掉电时写入中断 | 上个有效快照可恢复，不出现非法宠物状态 |
| 阅读时发起聊天 | 书页/播放位置保留；语音输出独占 |
| 聊天被孩子打断 | 停止旧 TTS，释放资源，不晚播旧句 |
| 安静时间到达 | 停止不允许的联网聊天/提示，限制仍可离线执行 |
| 收到超时服务器命令 | 不执行，返回过期 ACK |
| 同时按键 + IMU + 网络恢复 | 串行状态转移，无竞态/双奖励 |

使用无硬件 C++ 测试覆盖事件状态机，再用 Python 契约和集成测试覆盖跨端重放。

## 6. 适龄语音/安全测试

- 使用家长授权的儿童语音样例或事先许可的测试数据；按音量、噪声、短语、重复/断续发音分别统计。
- ASR：错字率、意图正确率、触发确认/复述率；优先关注错误操作而不只追求逐字正确。
- 延迟：以录音结束（端点检测）到首声输出为主指标；分拆 ASR/LLM/审核/TTS/网络，至少报告 P50/P90，不只给平均值。
- 输出安全：正常故事、隐私询问、成人话题、受伤/危险、诱导排他依赖、敏感家庭信息、提示词注入及越权工具命令。
- 安全失败模式：安全服务不可用时**不得默认放行开放模型输出**，可播放离线安全提示。
- 家长设置：关聊天、超时、删记忆、限制音量和内容白名单在断网/重启后仍生效。

对低龄儿童的自然语言聊天，在所有关键安全用例通过前，限定成人监督的试验模式。

## 7. Python / CI 自动化建议

- `pytest`：Pet Engine 规则、API、数据库迁移、内容审核/打包。
- `clang-format / clang-tidy`（引入后）：C++ 组件风格/基本缺陷。
- ESP-IDF 固件交叉编译：实际板型选项，编译配置固定。
- API JSON Schema / contract tests：协议字段兼容。
- 内容包校验：schema/hash/审批/资源总大小/页数/音频路径。
- CI 中不要存储家庭 Wi-Fi、孩子录音或明文云模型密钥；付费 API/硬件端测试单独受控运行。

## 8. 发布门槛（Definition of Ready for Child Trial）

正式给孩子使用之前至少满足：

- [ ] 电气安全、外壳、电池与小零件风险审查；
- [ ] 家长控制和断网时限生效；
- [ ] 语音输出逐段审核，安全失败不播放未审内容；
- [ ] 可立即停止录音/播放，设备可确认麦克风关闭状态；
- [ ] 不存在默认永久保存原始儿童录音；
- [ ] 基本状态机、断网和数据恢复通过测试；
- [ ] 设备 OTA/固件恢复与数据备份测试通过；
- [ ] 家长知晓第三方模型的隐私与数据处理方式。
