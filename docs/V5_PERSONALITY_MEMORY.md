# V5-01..03：个性与记忆（纯 C++ 核心）

对应 `DEVELOPMENT_PLAN.md` V5-01/02/03、ADR-012、`PRODUCT_REQUIREMENTS.md` §8、`INTERFACES_AND_DATA.md` §5.1。
代码在 `firmware/components/kid_app`，全部是无 I/O 的纯 C++，由 `scripts/p2_test.sh` 在 CI 里用 `g++ -Wall -Wextra -Werror` 跑。

## 1. Personality（V5-01）

`include/kid_app/personality.h`

- 三种性格 `Temperament`：`Curious` 好奇 / `Gentle` 温柔（默认）/ `Lively` 活泼。由家长设定，模型不能改。
- `PersonalityParams`：口头禅（话术模板 id）、默认表情倾向、首页五项（聊天/读书/游戏/喂食/睡觉）的基础提议权重。好奇偏读书，温柔偏聊天，活泼偏游戏。
- 话术库：42 条审核过的中文模板（3 性格 × 7 场景 × 2），每条有稳定 id：`(性格+1)*100 + (场景+1)*10 + n`。
  场景：问候、早安回顾、提到喜好、喂食、邀请读书、睡前、咯咯笑（V5-04 新增，轻摇时说，id x71/x72）。模板只含 `{book}` / `{like}` 两种记忆槽位，没有自由文本生成。
  **已发布的 id 含义不得修改**，新增文案用新 id（音频片段和家长审核都按 id 引用）。
- `SelectPhrase(...)`：只在槽位可用时选带槽位的模板（有读过的书才会说《{book}》，有选过的喜好才会说{like}）。早安回顾的“昨天我们读了《{book}》”只在 `current_day - 1` 那天确实读完过书时才会选（`MemoryStore::BookReadOn`），其他场景用任意最近读过的书；带槽位模板权重 3、通用模板权重 1；每个“性格×场景”都有通用兜底句，所以合法输入一定返回一个 id。
- `Propose(temperament, DayPhase, seed)`：按日相调整权重后挑一个首页提议。夜间/午睡只提议睡觉；早上喂食 +2；傍晚读书 ×2、不提议游戏、提议睡觉。
- 确定性：没有随机源，只用调用方传入的 `seed`（例如账本 generation）经固定整数哈希选择。**同输入同输出**，测试里还钉了几个跨编译器的黄金值。

## 2. MemoryStore（V5-02）

`include/kid_app/memory_store.h`，固定 288 字节小端编码。

| 层 | 内容 | 上限与淘汰 |
|---|---|---|
| 今日 `Today()` | 日期（本地日序号）、喂食/问候/读完书/完成游戏/选择题次数、最后一本书、最后一个游戏 | 每项饱和到 250；换日时整体归档 |
| 昨日 `Yesterday()` | 上一个**有活动**的日子（给 V5-04 早安回顾用） | 只保留 1 天 |
| 喜好 `PreferenceAt()` | `{slot, option, source_event}`，slot/option 是内容包白名单 id | 16 条；同一 slot 重答则覆盖并移到最前；满了淘汰最久没选过的 |
| 成长 `GetGrowth()` | 读完书数、完成游戏数、选择次数、活跃天数、里程碑位 | 计数饱和到 65535；里程碑只增不减（清空除外） |
| 最近书目 `RecentBookAt()` | 最近读完的书 id，新的在前 | 8 本；重读移到最前；满了丢最旧的 |

- 换日规则：记忆事件和宠物动作（`ApplyDurably(event, effects, day)`）都带 `day`（本地日序号，0 = 时钟未知）。板上接线时必须传 RTC 日期，否则只喂食的日子不会换日。`day` 更大 → 归档今天、开新的一天；`day` 相同或 0 → 计入今天；`day` 更小（时钟回拨）→ 只计入成长/书目/喜好，不改今天。时钟未知时产生的活动归到第一次知道日期的那一天。
- 里程碑：第一本书、5 本、10 本、第一个游戏、10 个游戏、第一次选喜好、活跃 7 天。
- 解码严格且只接受规范形式：未用条目、填充、保留区必须为 0；重复 slot/书目、超容量、未知里程碑位、昨日不早于今日等都判为损坏。

## 3. 写入路径守卫（V5-03）

所有写入都走 `MemoryStore::Apply(MemoryEvent)`，事件只有结构化字段（种类、来源、日序号、slot、option），没有任何文本。

| 事件 | 允许的来源 | 说明 |
|---|---|---|
| `PreferenceChosen`（PREFERENCE_CHOSEN） | **仅 `DialChoice`** | 写喜好的唯一路径 |
| `BookFinished` / `GameCompleted` | `DialChoice` / `Button` / `Device` | 只能由设备上的规则产生 |
| `MemoryCleared`（MEMORY_CLEARED） | **仅 `Parent`** | 一键清空 |
| `TemperamentSet` | **仅 `Parent`** | 家长设定性格 |
| 任意事件 | `Voice` / `Network` 一律拒绝 | 不从自由语音或未鉴权数据写记忆 |

另外：事件 id 为 0、slot/option 为 0、性格越界、未知种类/来源都拒绝；被拒绝的事件不改变任何状态。
没有任何其他 API 能写喜好。

**家长清空**：清掉今日、昨日、喜好、成长、最近书目，回到“刚认识”；**性格保留**；宠物状态（喂食数、模式）和外发队列不受影响。

**给语音服务的最小摘要** `MakeMinimalSummary()` / `FormatMinimalSummary()`：只含性格、喜好的 `{slot, option}`、今日四个计数、最近一本书 id、里程碑位，输出紧凑 JSON，例如：

```json
{"trait":"gentle","preferences":[{"slot":2,"option":31}],"today":{"feed":2,"greet":0,"books":1,"games":0},"last_book":17,"milestones":33}
```

不含事件 id（审计用的 `source_event`）、日期、名字或家长备注。传入当前日序号时，如果记忆里的“今天”已经是旧日期，今日计数报 0，不会把过期的“今天”交给语音服务。

## 4. 进入账本事务：PetAtomicLedger schema v2

- `PetAtomicLedger` 的单块 NVS blob 从 v1（1,480 字节）升级到 v2（1,768 字节）：原有 28 字节头 + PetCheckpoint + 16 条外发队列不变，在 CRC 之前追加 288 字节记忆块；头里的版本号 1→2、长度字段同步更新。
- `RecordMemory(MemoryEvent)`：校验 → 与宠物状态、外发队列一起**一次提交**。记忆事件与宠物事件共用同一个 128 条重放 id 窗口，所以同一个 id 重放（断电重启后、或两种事件撞 id）返回 `Duplicate`，**绝不重复计数**。写入失败时内存状态不变，同一 id 可重试。
- `ApplyDurably(PetEvent, effects, day)` 在同一次提交里给当天的喂食（Feed）/问候（Pickup）计数并按 `day` 换日，重复事件同样不计。`day` 默认 0，现有调用方不受影响。
- 取舍：记忆事件占用宠物事件的 128 条去重窗口。窗口本来就有上限；记忆事件很稀疏（读完一本书、答一道题），实际影响很小。若将来有来源会重放很旧的 id，再考虑扩窗口。
- **迁移**：`Store::Read` 现在返回实际长度。读到 1,480 字节的 v1 blob 时按 v1 严格校验（魔数、版本 1、长度、CRC、规范编码），宠物状态、重放窗口和外发队列原样恢复，记忆为空（v1 没有记忆）。下一次提交把 v2 写到另一个槽位，**v1 槽位保持原样**作为回滚副本；不擦除任何数据。其他长度一律按损坏处理（不自动擦除）。
- 旧的 `kid_pet` / `PetCheckpointCodec`（板上当前在用的 legacy 存储）没有改动，字节格式不变。

## 5.1 环境小常识（V4-03）

状态栏的 SHTC3 温度之上，房间太热或太冷时团团用一句儿童适宜的生活小常识提醒（多喝水、加衣服）。逻辑是纯 C++ 的 `EnvTipPolicy`（`env_tips.h/.cc`，`tests/cpp/test_env_tips.cc`），话术是 V5 话术表里新增的两个语境，复用同一套性格选句和 KPS1 声音包。

**判定**（读数每个心跳 10 s 发布一次，策略按时间判断，不数次数）：

| 项目 | 取值 |
|---|---|
| 太热 | ≥ 28.0 °C 连续保持 60 s 进入；< 26.0 °C 保持 60 s 才算恢复 |
| 太冷 | ≤ 16.0 °C 连续保持 60 s 进入；> 18.0 °C 保持 60 s 才算恢复 |
| 回滞 | 两个区间各有 2 °C 重叠带，重叠带内保持原状态，不反复触发 |
| 提醒时机 | 进入时一次；之后每 2 小时在原状态内再提醒一次 |
| 每日上限 | 每个本地日（RTC）最多 3 次（热/冷合计）；时钟没设置时按每次开机计 |
| 安静时段 | 家长安静时段（`RhythmScheduler::QuietAt`）内不说；提醒挂起，超过 30 min 就作废，不会清早才说“好热” |
| 说话时机 | 只在清醒的宠物首页、小智空闲、不在家长菜单/游戏/早安窗口/睡觉/午睡时；进入宠物模式 10 s 内先让问候说 |
| 开机第一次读数 | 只建立状态，不提醒 |
| 传感器读失败 | 保持计时重新开始 |

**板载发热**：SHTC3 紧挨着发热的主板和充电电路。V1-07 的实测只有一条（插 USB、正常室温：`temp_c10=284`，不补偿会直接落进“热”区），0/10/30 分钟偏差表还没测。所以先用保守估计：判定前先减去 `kUsbHeatC10 = 3.0 °C`（USB 供电）/ `kBatteryHeatC10 = 1.0 °C`（电池），两者都不超过可能的真实自热，宁可少提醒；V1-07 测出偏差表后只改这两个常数。状态栏仍显示传感器原始值。自测的 `temp` 注入值视为室温，不补偿。湿度暂未接入（板端只读温度，策略只看温度）。

**开机第一次读数**只建立状态不提醒：刚唤醒宠物时，房间本来就热/冷，不该马上说教；之后离开该区再回来才会提醒。

**话术**（`PhraseContext::HotTip` / `ColdTip`，每种性格各 2 句，共 12 句，id 181/182/191/192、281/…、381/…）：一句小常识加一个小动作，例如“今天有点热，记得多喝水，别在太阳下玩太久。”“有点冷了，记得加件衣服，别着凉。”文案需家长审核；`tools/sound_pack.py` 的清单（`docs/V2_SOUND_PACK.md`）已含这 12 句，可以录音。

**画面与声音**：触发时在首页播一个 5 s 的气泡动画（`ScenePose::TipHot` / `TipCold`，`Animation::TipHot` / `TipCold`）：热 = 头两侧汗滴 + 一杯水的想法气泡；冷 = 发抖线 + 一件外套的想法气泡。气泡避开状态栏两个保留框，只改肖像区。声音走已有的 `PostPhrase` 路径：TF 卡有声音包就播录音；没有声音包时播一段很轻的提示音（上行/下行小旋律，不是语音）。电子纸场景没有汉字字库，所以“只显示文字”落在串口日志的 `PET_ENV_TIP` / `PET_PHRASE_PLAY id=…`，屏上用图形气泡表示。

**日志**：

- `PET_ENV zone=normal|hot|cold room_c10=.. src=shtc3|selftest`（区域变化）
- `PET_ENV_TIP_PENDING kind=hot|cold`（越阈值并保持够久）
- `PET_ENV_TIP kind=.. acted=1 room_c10=.. today=N`（真的说了）、`PET_ENV_TIP_HELD reason=quiet kind=..`（安静时段挂起）
- 随后 `PET_ANIM_DONE name=tip_hot|tip_cold`、`PET_PHRASE_PLAY id=.. ctx=hot_tip|cold_tip src=pack|chime`

**自测**：`tools/selftest/v4_env_tips.pettest`（25 % 缩放，约 136 s，监视上限 146 s）。开头的基线 `temp 22` 先保持满 60 s（缩放 15 s），保证无论真实传感器开机时在哪个区都先回到 normal。新增 PETSELFTEST1 步骤 `temp <0..60>` / `temp off`：像 `battery` 步骤一样替代 SHTC3（同时驱动状态栏和提醒策略）；缩放后 60 s 保持变 15 s。场景依次 31 °C → 22 °C → 12 °C，期望热提醒、无提醒恢复、冷提醒。**必须在家长安静时段之外运行**，否则会看到 `PET_ENV_TIP_HELD`。原速运行：`--timescale 100`。
