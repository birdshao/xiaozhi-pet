### 由本轮引出的修改（PR #44 后续提交）

1. **拨轮方向对调**：按孩子操作的方向，上 = GPIO6，下 = GPIO4，按下 = GPIO5。（2026-11-07 按用户要求对调为**上 = GPIO4、下 = GPIO6**）原理图的 Button_Up/Button_Down 是按板子自身方向标的。
2. **释放去抖**：松开后 120 ms 内再次按下视为同一次按住（时长从第一次按下算起）；短按/说话/哄睡事件因此延后 120 ms 发出。
3. 自检日志改为按 GPIO 编号输出，避免再与"上/下"语义混淆。

### V1-04 时钟校时：通过

- 开机 12 s 时系统已有服务器时间，`PET_DIAG_RTC_SYNC ok=1 was_stopped=1`，写入 2026-11-03 17:12:52（本地时间）。
- 经历一次 PMIC 关机和一次芯片复位后，再次读到 `osc_stopped=0`、17:18:21，时间连续。

### V1-05 定时开机：用户观察通过，日志间接佐证

- 用户确认：宠物模式下按住 BOOT + 拨轮中键 5 s 后关机，约 90 s 后自己开机。
- 这段在电池供电下进行，串口断开，没有录到 `PET_DIAG_ALARM_TEST` 和闹钟开机那次启动的 `PET_DIAG_WAKE`。
- 间接佐证：插回 USB 时芯片被复位（`rst:0x15 USB_UART_CHIP_RESET`），该次启动读到 `alarm_irq_enabled=0`。测试会先打开闹钟中断才关机，中断被关掉说明中间确实有过一次启动并执行了清除，也就是闹钟开机。
- 结论：PCF85063 闹钟能把 PMIC 关机状态的板子开起来。作息里的"定时起床"可以基于这个能力设计。

### V1-03 姿态：通过，阈值初值

±4 g、62.5 Hz、500 ms 窗口；`dev` = 窗口内 | |a| − 1 g | 的最大值。

| 动作 | 观察 | 建议判定 |
|---|---|---|
| 屏幕朝上静置 | z ≈ −983 mg，\|a\| 983–987，dev 16–19 | 噪声底 < 40 mg（按实测静置幅值归零后判） |
| 拿起举着 | 平均倾角明显变化（y 0→~550 mg），过渡窗 dev 230–240 | `Pickup`：静置后 dev > 150 或倾角变化 > 300 mg，再稳定 |
| 轻轻摇 | \|a\| 690–1420，dev 370–420 | `GentleShake`：连续 2 窗 dev 250–800 |
| 稍用力摇 | \|a\| 230–2570，dev 1330–1570 | `HardShake`：任一窗 dev > 1000（不奖励） |
| 屏幕朝下扣 | z 翻到 ≈ +1010 mg，稳定 | `FaceDown`：z > +800 持续 ≥ 1 s |

第一个窗口仍有一个异常大值（6,863 mg），手势识别要丢弃配置后的第一个窗口。
