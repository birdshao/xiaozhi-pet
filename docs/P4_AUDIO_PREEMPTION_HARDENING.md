# P4 离线绘本音频：翻页和小智语音抢占加固

这次修复在 #39 的实际板卡 PCM 通路上做三个行为改动：

1. 进入新书页前若上一页或小智语音还在硬件输出任务的待播队列中，`BeginLocalStoryPcm` 不再抢先把新页覆盖到队列中；本地 SD 音频任务最多重试 100 次，每次退避 10ms，在其间收到新的翻页或停止请求则立即优先处理。仅测试用的缓存/队列控制，不存在新的 I2S 写入者。
2. 网络语音片段被 `PushPacketToDecodeQueue` 成功接纳时，就在同一 `audio_queue_mutex_` 保护下把当前书页音频会话设为无效，避免仅等 `Application::SetDeviceState` 再处理。被拒绝的网络包不会触发抢占。
3. `PetCommitted` 一旦提交改变场景或页码的持久事件，就立即调用 `CancelLocalStoryPcm`，**先停止旧页声音再开始漫长的 EPD 刷新**，不必等待后续 SD worker 恰好调度到。显示完成之后才允许新页 PCM 排队。

通过本地源代码合约测试、原有场景/状态机回归以及 ESP-IDF 正式 Waveshare 板级编译后才合并。真实实体扬声器仍须测量音频尾音和抢占延迟。当前输出任务在校验 session 后到调用 `OutputData` 仍存在一个短暂调度窗口，不承诺采样级立即中断；如果要做到硬切，应在下一个阶段设计单个音频任务的控制消息和更严格的停止确认。

测试日志应分别关注：旧页 0–40ms 缓冲排空、点击新页后被丢弃/抢占的语音、设备从 Listening/Speaking 恢复 Idle 后是否需要用户重新启动绘本。绝不尝试多任务并发驱动 ES8311。
