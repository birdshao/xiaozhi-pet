# V2-08 声音包（KPS1）与 V5-04 宠物短句（前半）

对应 `DEVELOPMENT_PLAN.md` V2-08、V5-04，`PRODUCT_REQUIREMENTS.md` §3（喇叭、TF 卡）、§8.1，ADR-012。

## 1. 做了什么

团团说的话只有两类，全部是**审核过、提前录好**的音频，没有任何自由文本生成或语音合成：

| 声音 | 什么时候 | 来源（按顺序找，找到为止） |
|---|---|---|
| 选项名（聊天/故事/游戏/喂食/睡觉） | 拨轮停在首页某一项上（V2-07） | TF 卡声音包 → 固件内置的 5 段提示音 |
| 宠物短句 | 见下表 | TF 卡声音包 → 每个场景一段很短的内置提示音（固件现算，不占 flash） |

| 场景 | 触发 | 话术场景（`PhraseContext`） |
|---|---|---|
| 打招呼 | 拿起团团；首页选“聊天”“游戏”（目前两者都是“团团说你好”） | `Greeting` |
| 早安 | RTC 定时开机后的早安画面（V3-04） | `MorningRecap`（只用不带 `{book}` 的那句） |
| 好吃 | 喂食提交后 | `Feed` |
| 咯咯笑 | 轻轻摇 | `Giggle`（新增场景，id x71/x72） |
| 晚安 | 哄睡：睡觉画面出现时（按 PWR 或首页选“睡觉”） | `Bedtime` |

规则：

- **选句确定**：`PhrasePlanner` 用 `Personality::SelectPhrase` 在该性格、该场景的无槽位句里选，种子是“这个场景本次开机已经说过几次”。同样的事件顺序、同样的性格，说的句子完全一样；同一场景的两句会轮换。
- **不刷屏**：一句话之后 4 秒内的新短句直接跳过（`PET_PHRASE_SKIPPED`），不打断正在播的声音；早安、晚安例外。
- **不打扰**：小智语音会话中、Pet 模式外、睡着（关机流程）和午睡时不说；晚安只在入睡画面的那几秒说，取消入睡或关机时立刻停。
- **音量**：和选项名完全同一条软件音量通路（`ScalePcm(..., PromptVolumePct())`）：安静时段 30%、自测 `volume` 生效；从不改小智保存在 NVS 里的 codec 音量。
- **一条音频通路**：选项名和短句都由同一个 `pet_prompt` 任务经小智 `AudioService` 的本地 PCM 接口播放，新请求覆盖旧请求。
- **性格**：家长设置性格（V5-06）之前，固件固定用**温柔型**。

## 2. 录音清单（给录音的大人）

### 先录哪些

固件现在只用温柔型，所以**最少录 14 段**：5 个选项名 + 温柔型 9 句（表里 `2xx` 开头的）。好奇型（`1xx`）和活泼型（`3xx`）以后支持换性格时再补也行。没录的那段自动用内置声音，不会出错。

### 录音要求

- 安静的房间，手机录音就行；格式不限（m4a、mp3、wav 都可以），**一段一个文件**。
- **文件名 = 下表“文件名”一列**，例如 `chat.m4a`、`211.m4a`。放进同一个文件夹（下面叫 `my_recordings`）。
- 选项名不超过 2 秒，短句不超过 6 秒（超出部分会被截掉）。开头结尾的空白和音量不用管，工具会自动剪掉静音、统一响度。
- 语气：慢、清楚、温柔，像对 3–5 岁的孩子说话；不要背景音乐和音效。
- **一字不改**地照着“要说的话”念：这些句子是审核过的话术，改词要先改 `firmware/components/kid_app/src/personality.cc` 的话术表并重新审核（表里的 id 含义永远不改，新文案用新 id）。
- 录完每段自己听一遍；打包命令要求加 `--reviewed`，表示有大人听过每一段。

## 3. 把录音变成声音包

需要 Python 3.10+，以及在 PATH 里的 `ffmpeg`。在仓库根目录执行。

**一条命令**（转换 + 打包）：

```bash
python -m tools.sound_pack build my_recordings --output build/sounds/default.kps --reviewed
```

得到 `build/sounds/default.kps`（复制到 FAT32 TF 卡的 **`/sounds/default.kps`**）和 `build/sounds/default.manifest.json`（每段的 id、文字、时长、CRC、整包 SHA-256，以及哪些段没录、会用内置声音）。

同时把 5 个选项名换进固件内置提示音（没插卡时用；要重新编译固件并提交这 5 个 wav）：

```bash
python -m tools.sound_pack build my_recordings --output build/sounds/default.kps --reviewed --embed
```

（只换内置选项名也可以用原来的 `python -m tools.make_prompt_audio convert my_recordings`。）

**分步做**（想先逐段试听转换结果时）：

```bash
python -m tools.sound_pack convert my_recordings build/clips
```

```bash
python -m tools.sound_pack pack build/clips --output build/sounds/default.kps --reviewed --revision 1
```

```bash
python -m tools.sound_pack verify build/sounds/default.kps
```

`--revision` 是你自己的版本号（写进包头和日志，便于确认卡里是哪一版）。工具拒绝：不在清单里的文件名、带 `{book}`/`{like}` 的句子、非 24 kHz 单声道 16 bit、太短（< 0.1 秒）或太长的片段、没有 `--reviewed`。

**只测 TF 通路**（不是给孩子的内容，全是合成提示音）：

```bash
python -m tools.sound_pack demo --output build/sound-smoke
```

把 `build/sound-smoke/sounds/default.kps` 复制到卡上 `/sounds/default.kps`；三种性格的短句音高不同，日志里应看到 `src=pack`。

## 4. 固件行为与日志

- 进 Pet 模式时，绘本代码挂载 TF 卡（`/sdcard`，只读用途，从不格式化）；之后 `pet_prompt` 任务打开 `/sdcard/sounds/default.kps`，先校验包头、目录和**每一段**的 CRC，任何一处坏了整包不用。之后不再重试：**换卡要重启**。
- `PET_SOUND_PACK state=ready|absent|invalid|no_sd clips=N rev=R ms=T`：`absent` = 卡在但没有包，`invalid` = 包损坏/格式不对，`no_sd` = 没卡或挂载失败。
- `PET_PROMPT_PLAY index=<0..4> ... src=pack|embedded`，`PET_PROMPT_QUEUED/INTERRUPTED/FAILED index=...`（原有格式不变，只在 PLAY 行末尾加了 `src=`）。
- `PET_PHRASE_PLAY id=<话术 id> ctx=greeting|morning|feed|bedtime|giggle|hot_tip|cold_tip src=pack|chime ...`，`PET_PHRASE_QUEUED/INTERRUPTED/FAILED id=...`，`PET_PHRASE_SKIPPED ctx=... reason=gap`。
- 自测：`tools/selftest/v5_phrases.pettest`（拿起、两次轻摇、喂食、哄睡后取消，期望 `phrase_seq 211,272,241,261`）；早安那句在 `v3_morning.pettest` 的日志里看 `ctx=morning`。`tools/selftest_report.py` 新增 `phrase_seq` 期望。

## 5. KPS1 格式

小端，固定布局，Python `tools/sound_pack.py`（`encode`/`decode`）与 C++ `sound_pack_reader.h` 按同一规则检查，`scripts/p2_test.sh` 用 Python 生成的包跑 C++ 读取器。

- 包头 32 B（`<4sHHIIIIII`）：`KPS1`、版本 1、片段数 1–192（V8 起；原为 1–96，旧包仍可读）、采样率 24000、revision、数据起始（= 32 + 16 × 片段数）、总字节数（= 文件大小）、目录 CRC32、包头前 28 字节的 CRC32。
- 目录每段 16 B（`<HHIII`）：片段 id（严格递增，1–1999）、保留 0、偏移、字节数（偶数，≤ 6 秒）、CRC32。
- 数据：去掉 RIFF 头的 24 kHz 单声道 little-endian PCM16，每段从 4 字节对齐处开始，中间只有补零，最后一段结束即文件结束。整包 ≤ 8 MiB。
- 片段 id：`1 + 首页项序号`（1 聊天 … 5 睡觉）是选项名；`100–999` 是 `personality.cc` 话术 id；`1000–1999` 是 V8 `care_phrases.cc` 护理话术 id；6–99 留给以后的音效。

为什么不叫 KPB2：KPB2（`docs/V4_KPB2_CONTENT_FORMAT.md`）是绘本格式，给声音包保留了包类型值 `2 soundpack`，但规定“别的包可以用自己的魔数和格式，只有共用 KPB2 外壳才必须用保留类型值”。声音包用自己的魔数 `KPS1`、自己的目录 `/sounds/`，manifest 里的 `package_type` 写 `soundpack`（与保留值同名）；KPB 读取器看到 `KPS1` 魔数会拒绝，KPS1 读取器看到 `KPB1`/`KPB2` 也会拒绝（双方都有测试）。两者只共用只读文件接口 `StoryPackFile` 与 SD 挂载。CRC32 只防随机损坏，不是签名，不防故意篡改。

- 真机未验证：TF 卡上整包校验耗时（demo 包约 0.7 MB）、喇叭实际音量、绘本朗读和短句同时读卡时是否顺畅（FAT 最多同时打开 3 个文件：绘本、朗读、声音包正好用满）。
