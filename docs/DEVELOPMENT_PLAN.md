# 详细开发计划：xiaozhi-pet

**版本**：v0.1 / 2026-10-25  
**状态**：规划，不代表代码、硬件测试、服务器部署已完成  
**已选路线**：小智开源 ESP32 固件 + 自建小智 Python 语音服务端 + 独立 Python 宠物/学习服务。官方云**只用于硬件/语音基线对照**，不开发正式业务分支 B。

## 0. 目标、方法和里程碑

目标：用 Waveshare ESP32-S3-ePaper-3.97 做出 3–5 岁适龄的**可离线互动的电子宠物 + 可选 AI 对话 + 经审核绘本/学习**，保障可更新、可恢复和家长可控。

工作方法：
- **先验证最大不确定性**：墨水屏图形质量/刷新、硬件输入、内存和音频，再铺开业务。
- **先设备后云端**：本地 PetEngine 先可运行，再接入自建语音服务；不让 LLM 控制物理 UI。
- **阶段门禁**：每阶段必须产出代码/文档/测量/验收记录，不能因为演示可用就宣布完成。
- **并行边界**：Python 纯业务模型可在 P1/P2 并行研发，但最终联调依赖 P0/P1 的板级基线。
- **MVP 版本定义**：P2 是“离线宠物 MVP”，P3 是“语音宠物 alpha（家长监督测试）”，P4 是“学习型宠物 beta”；P5 才是“面向长期使用的试用版”。

### 总体依赖

```text
P0 硬件基线
 ├─> P1 EPD/宠物 UI 技术验证 ─> P2 本地宠物 MVP ─┐
 └─> P3 自建语音环境/协议 PoC（可前置启动） ───┤
                                                   v
                                          P3 语音-宠物联动
                                                   |
                                          P4 故事与学习
                                                   |
                                          P5 稳定性/家长使用
```

## P0：硬件及上游基线

**目标**：明确实际开发板能力，固化一份可重复编译/烧录的基线。  
**前置条件**：真实开发板、USB、扬声器、电脑上的 ESP-IDF 环境；原版开发资料可访问。  
**交付物**：`docs/hardware/BOARD_BASELINE.md`、`version-lock.json`、最小官方固件 build/flash 记录和原厂备份。

| ID | 具体任务 | 验收证据 |
|---|---|---|
| P0-01 | 查看并记录实物型号/批次、接口、电源、板载麦克风/扬声器连接、实际按键和是否真有旋转输入 | 正反面照片/实测输入清单（不上传儿童信息） |
| P0-02 | 固定上游 `78/xiaozhi-esp32` 具体 commit/tag 与 ESP-IDF/组件依赖版本 | `version-lock.json` + 可复现安装指令 |
| P0-03 | 克隆并使用 `Waveshare ESP32-S3-ePaper-3.97` 板型编译/烧录/串口监控 | 可启动的固件、启动日志与 build 参数 |
| P0-04 | 用官方云做一次纯硬件语音对照：联网、录音、播放、打断、音量、重连 | 表格记录，不引入宠物业务 |
| P0-05 | 屏幕全刷/局刷/睡眠恢复的最小驱动调用验证 | 静态图片+刷新日志与照片 |
| P0-06 | 测试 BOOT/PWR、可用外接输入/拨轮（如果存在）、I²C 设备扫描与 IMU 数据 | GPIO/总线映射与输入事件记录 |
| P0-07 | SD 卡初始化/读写原型，确认与显示/音频 SPI 或 SDMMC 是否资源冲突 | 小文件/连续读取日志 |
| P0-08 | 获取 Flash 分区、应用镜像体积、PSRAM/heap/任务栈初始值、供电与休眠基线 | 内存及分区预算表 |
| P0-09 | 评估上游导入方式：外部 checkout + patch、submodule 或 fork；选能重复构建且易更新的一种 | ADR-007 定案、CI 草稿 |
| P0-10 | 建立工程模板、文档结构、格式化与固件最小 CI | 一条完整从 checkout 到 build 的步骤 |

**Gate P0**：官方小智语音、屏幕、输入、SD/IMU（不支持的功能明确记录）、PSRAM/分区情况均有真实结果，板型固件能自行重建。不要求 P0 就实现 SD 音频播放器。

### P0 必须明确的风险

- 当前官方板级源码主要注册 BOOT/PWR，不应假设旋转控制已接入；若实物无拨轮，MVP 使用可用按钮，设计外接输入的可选硬件。
- `custom_lcd_display.cc` 的局刷调用不是最小矩形局刷完整实现，P1 须另作原型。
- 微雪现成小智固件并不等于可直接播放 SD 音频。
- 16MB Flash 下双 OTA + 大资源分区可能紧张；资源优先 SD，不盲目占用固件 Flash。

## P1：墨水屏 PetDisplay 技术验证

**目标**：把“能否做成可爱的宠物画面和交互”变成真机数据，尽早淘汰不合适的渲染方案。  
**依赖**：P0-03、P0-05、P0-08。  
**交付物**：`PetDisplay` 原型、表情资源、`EPD_BENCHMARK.md`、交互演示。

| ID | 任务 | 验收 |
|---|---|---|
| P1-01 | 自定义全屏宠物首页布局、静态黑白形象和 5–8 种表情资源 | 实机显示可辨识，适龄视觉设计 |
| P1-02 | `SceneModel` 设计：宠物、配饰、情绪、场景、字幕/页码状态 | 纯数据可重现完整页面 |
| P1-03 | `SceneComposer` 由 SceneModel 生成全屏/局部变化，不依赖默认聊天消息 UI | 从聊天页面切换到宠物首页 |
| P1-04 | 对照官方 `CustomEpdDisplay` 研究/修正脏区处理、帧缓冲转换和物理局刷窗口 | 局刷画面无缺块/旧帧残留；保留全刷后备 |
| P1-05 | `RefreshScheduler`：去抖、合并频繁请求、BUSY/超时、鬼影恢复 | 多事件并发不死锁/不阻塞音频 |
| P1-06 | 测试全刷、局刷、反复切换、休眠恢复；记录时间/残影/PSRAM | `EPD_BENCHMARK.md` 真机表格 |
| P1-07 | 调整显示线程锁、SPI/UI任务与语音任务优先级 | 小智正常聊天时不会明显掉音或 WDT |
| P1-08 | UI 复用隔离：仅在 `DisplayPort` 与 BoardAdapter 使用上游显示类，宠物界面不直接耦合内部消息控件 | 可替换 mock display 做单测 |

**Gate P1**：能从按钮/模拟事件切换“首页→开心→疑惑→睡觉→绘本占位页”；刷新正确、能稳定运行；记录可接受的效果与明确不能实现的动画类型。若局刷不可靠，先采用限频全刷，不阻塞 P2。

## P2：离线宠物 MVP

**目标**：即使完全断网，也有真实可玩的宠物，不是孤立的 UI Demo。  
**依赖**：P1-02/03、P0 输入/存储基线。  
**交付物**：可独立运行的 `PetController`、本地持久化、输入与基础音效、状态机单测。

| ID | 任务 | 验收 |
|---|---|---|
| P2-01 | 纯 C++ PetEngine 状态机 + 独立事件队列 + `event_id` 幂等模型 | 事件转移单元测试、重复执行不双奖励 |
| P2-02 | 定义 `HOME/PET/GAME/CHAT/READER` 场景与 `IDLE/INTERACT/QUIET/SLEEP` 运行状态 | 切换状态不影响显示或音频一致性 |
| P2-03 | BOOT/外接输入：短按、长按、多状态入口、去抖；可用时接入拨轮 | 不误触电源、不与原语音键冲突 |
| P2-04 | IMU 起立/放下/轻晃识别：阈值滤波、误报和误触处理 | 静止误报可测，有关闭选项 |
| P2-05 | NVS 原子存档、版本、checksum、恢复与写入节流 | 断电模拟/重启后恢复上个有效状态 |
| P2-06 | 音效播放最小 `AudioCoordinator`：短音效、停止、音量、语音抢占模拟 | 无重叠播放、资源释放与优先级正确 |
| P2-07 | 喂食/玩耍/睡眠/换简单配饰本地规则；不含饥饿死亡/惩罚 | 纯离线完整互动 |
| P2-08 | 本地家长安全默认值：最大音量、静音/安静时段、禁聊天开关占位接口 | 断网保留策略且不会被儿童轻易修改 |
| P2-09 | 连续互动和重启回归，记录内存、声音和屏幕状态一致性 | 一轮稳定性报告 |

**Gate P2**：关闭 Wi-Fi 仍可从休息进入宠物互动、播放本地提示、喂食、切换表情、保存状态并重启恢复。这就是第一版真正的产品 MVP。

## P3：自建语音与宠物联动

**目标**：正式接入自建小智 Python 服务端，具备可审核的幼儿语音对话和设备场景联动。  
**依赖**：P0 的小智通信基线、P2 的 PetEngine；其中服务端部署可在 P1/P2 并行开始。  
**交付物**：锁定版本的自建语音服务、`VoiceAdapter`、`PetLearning API` 最小版、语音/安全基准。

| ID | 任务 | 验收 |
|---|---|---|
| P3-01 | 克隆部署 `xinnan-tech/xiaozhi-esp32-server`，锁定 commit、配置方式和依赖 | 本地/目标服务器可重复启动 |
| P3-02 | 选择一套 ASR + LLM API + TTS 基线，实现端到端对话 | 与板卡 WebSocket 或其他锁定协议可联通 |
| P3-03 | 测对话首声延迟、打断、噪声、短句及幼儿发音（授权样例） | 分阶段 P50/P90、识别和意图正确率 |
| P3-04 | 研究并实现语音处理节点的薄适配：ASR 结束、路由意图、回复审核、TTS 入队、对话结束 | 不改底层二进制音频协议 |
| P3-05 | FastAPI + SQLite 初始化：宠物资料、幂等事件、家长策略；本地/服务端状态对账 | API schema/数据库迁移有单测 |
| P3-06 | 设备独立业务桥接：事件上报、命令 ACK、断线重试、恢复同步及凭证 | Wi-Fi 反复断开无双奖励或旧命令误执行 |
| P3-07 | 确定性意图路由：翻页、暂停、退出、宠物喂食优先于 LLM | 至少固定命令在 ASR 成功时不依赖 MCP 调用 |
| P3-08 | 输入/输出安全门控及默认拒绝；不能让未审核模型分句提前进入 TTS | 失败关闭、违规提示与工具越权用例通过 |
| P3-09 | 对话角色设计：简短、3–5 岁适龄、承认是 AI、不过度拟人依赖 | 规范样例对话人工审查 |
| P3-10 | TTS/音频协调：聊天抢占本地音效、结束恢复、超时重连 | 30+ 轮混合互动无音频抢占错误 |
| P3-11 | 本地宠物表情与 AI 状态联动（听/思考/说/结束），屏幕事件节流 | 界面不随每个语音片段疯狂刷新 |
| P3-12 | 对比至少两种模型/ASR/TTS 配置的效果、数据处理规则与成本 | 一张可复验的技术选型记录 |

**Gate P3**：设备使用自建服务，能进行适龄问答，关键命令走确定性路径，输出文本进入 TTS 前经过审核，网络失败可回离线宠物。此阶段仅允许**家长监督下的功能测试**。

## P4：故事、绘本、学习与养成

**目标**：实现“儿童内容从 Python 生产到设备展示/播放”的完整链路。  
**依赖**：P1 PetDisplay、P2 存储/AudioCoordinator、P3 内容 API。  
**交付物**：内容包规范 v1、审核流水线、本地故事播放器、书页 UI、小游戏/学习进度。

| ID | 任务 | 验收 |
|---|---|---|
| P4-01 | 设计 v1 内容包 manifest、图片、音频、问题、审查标记、文件 hash 和兼容版本 | 格式文档和 JSON Schema 测试 |
| P4-02 | Python 内容生产工具：AI 草稿、旁白生成、自动分段、尺寸/格式转换、包打包 | 可生成一套样例动物绘本（草稿） |
| P4-03 | 家长审核/批准步骤（人工审核首版即可），审批前禁止同步到设备 | 无审批的内容无法被设备列表读取 |
| P4-04 | 固件 SD 文件系统、资源索引、下载/校验/断点恢复（可先通过电脑拷 SD） | 内容损坏会拒绝播放并回退 |
| P4-05 | 本地音频播放器：确认 Opus/WAV 等可用格式、缓冲和 AudioCoordinator 抢占 | 断网连续播放整本故事 |
| P4-06 | 绘本页面/音频同步：上一页/下一页/重复/暂停/续读 | 与画面和音频进度一致 |
| P4-07 | 当前页知识上下文提供给 VoiceAdapter；约束 AI 围绕本页问答 | 提问能指向当前正确页，避免越权内容 |
| P4-08 | 规则化小游戏：动物谜语/颜色/数字等；不依赖每轮模型即兴编题 | 离线或弱网仍可玩一组完整游戏 |
| P4-09 | 成长/配饰/纪念卡和进度入库；重复答题或重复事件不可刷奖励 | 重启/断网/重传后积分与道具一致 |
| P4-10 | 批量内容 QA：错别字、重复、年龄适配、版权/授权记录、语音音量校正 | 发布审核表和可重打包内容版本 |

**Gate P4**：一套家长审核后的绘本能展示、整本离线播放、准确翻页、被问“当前页是什么”时返回基于该页的回答；宠物的成长记录正常更新。

## P5：家长管理、OTA、稳定性与上游同步

**目标**：从实验品过渡到可控的长期试用版本。  
**依赖**：P0–P4。  
**交付物**：家长入口、安全测试报告、OTA/回滚演示、上游升级流程、发布版本。

| ID | 任务 | 验收 |
|---|---|---|
| P5-01 | 家长设置（聊天开关、安静时段、最长使用时长、音量限制、内容白名单） | 本地和服务器策略一致，断网仍强制最低保护 |
| P5-02 | 宠物记忆/学习记录查看与删除；默认不保存原始儿童录音 | 删除后无可从应用访问的旧记录，第三方数据处理另核验 |
| P5-03 | 设备绑定和最小权限 API 鉴权、HTTPS、密钥轮换 | 不同设备互相无法调用对方 API |
| P5-04 | 明确的录音/麦克风关闭方式与指示，避免“按键停止”被误认为硬件物理断电 | 人机说明及真机测试；如果需要物理断麦，补硬件设计 |
| P5-05 | 持续运行/重启/断网/SD 拔插/低电量/异常状态压力测试 | 无内存持续泄漏，错误可恢复并记录 |
| P5-06 | 自控 OTA 服务/镜像签名或校验/灰度/双分区/回滚，并核算 Flash | 断电升级演练不砖机、不损坏存档 |
| P5-07 | 自动化构建、Python 测试、协议契约、内容包和升级兼容矩阵 | CI 运行绿灯，硬件测试记录另存 |
| P5-08 | 选择更新的上游固件版本，完成第一次真正的“升级合并演练” | 上游变化只影响受控适配层，重要用例通过 |
| P5-09 | 儿童安全红队用例、家长可理解的限制说明、模型费用和隐私复核 | 关键安全问题无未处理高风险项 |
| P5-10 | 版本标注、发布说明、恢复/回滚手册、使用手册 | 可从备份恢复设备、内容和宠物状态 |

**Gate P5**：具备完整家长控制和数据清除、语音审核、故障恢复与 OTA 回滚验证，才可以考虑交由儿童日常使用；还须完成电池/外壳安全评估。

## 7. 任务执行优先级（关键路径）

**必须先做**：P0-01/02/03/05/08 → P1-01/03/04/05/06 → P2-01/05/06 → P3-01/02/04/07/08 → P4-01/05/06 → P5-01/06/09。

**可以并行**：
- P1：宠物黑白美术资源与底层刷新基准；
- P2：纯 C++ PetEngine 单测与 IMU/输入测试；
- P3：独立 Python PetLearning API 与音频服务端部署；
- P4：Python 内容生成器、人工审核工具与固件 SD 播放器；
- P5：安全用例和 API 契约测试可提前加入。

**不宜提前投资**：
- 很复杂的成长经济系统（先验证儿童愿不愿互动）；
- 实时口型/复杂动画（墨水屏硬件限制）；
- OID 点读识别硬件（等绘本内容包稳定后再接入）；
- 本地全套 LLM/ASR/TTS 模型（先测最小云 API 组合的体验、成本和隐私）。

## 8. 每项任务完成定义（DoD）

任一任务完成都应满足：
- 对应代码/配置/文档已入库，并记录使用的上游 commit；
- 至少有可复现的自动测试，或在硬件相关场景附真机步骤与日志；
- 出错和断网情况下的行为明确；
- 未引入硬编码密钥、未经审核的儿童资源、原始儿童录音；
- 影响数据/协议的变化有 schema 版本和迁移/兼容测试；
- 如修改上游文件，说明改动范围和合并风险。

## 9. 风险登记册

| 风险 | 可能后果 | 处理阶段/预案 |
|---|---|---|
| 墨水屏慢/局刷鬼影 | 宠物体验受损 | P1 硬件测试，退回静态限频全刷 |
| 旋钮不存在或未接入 | 导航 UX 无法按原方案实现 | P0 实物复核，BOOT/外置按键替代 |
| 音频与显示竞争 PSRAM/CPU | 卡顿、WDT 或掉音 | P0/P1 量测，统一队列/缓冲 |
| 自建语音延迟/幼儿 ASR 差 | 孩子失去兴趣、误操作 | P3 多配置对照、确定性确认 |
| 逐段 TTS 漏过审核 | 儿童安全问题 | P3 严格前置门控/失败关闭 |
| 本地和服务端数据冲突 | 奖励重复/状态丢失 | P2/P3 幂等序列与迁移测试 |
| SD 与 OTA/资源冲突 | 更新失败或内容损坏 | P0 分区检查、P4 完整性检验、P5 回滚 |
| 上游小智修改协议/UI | 集成层破坏 | P5 兼容矩阵+升级分支 |
| 平台/API 成本或政策变动 | 长期使用受影响 | P3 多提供商替换与支出预算 |
| 电池/外壳未儿童化 | 人身安全风险 | P5 不合格则禁止儿童使用 |
