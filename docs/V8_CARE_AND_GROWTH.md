# V8 养成与照顾（会话①）

团团多了“过日子”的一面：会饿、会困、会脏、会无聊（只是表情和小图标），孩子可以选菜喂她、
摇一摇给她洗澡、拨轮给她梳毛、轻摇挠痒、扣过来哄睡；成长里程碑会变成贴纸并解锁装扮和小屋家具；
睡前团团会念一页“今天”的日记；早上会说房间冷热、节日和今天的好习惯。

一切规则都在设备上、离线、确定性运行（只用 RTC 时间和账本里的数据，不用随机数，也不用大模型）。
**不惩罚孩子**：没有生病、死亡、扣分、掉级；需求最高也只是“想要”的表情和气泡。

## 1. 玩法

| 功能 | 孩子怎么玩 | 团团怎么反应 |
|---|---|---|
| 需求与心情 | 不用操作 | 饿 / 困 / 脏 / 无聊按时间慢慢上升（0–3 级）。≥2 级时首页团团旁出现一个想法气泡（小鱼 / 月亮 / 水滴泥点 / 小球）；困了是困倦的眼睛，无聊是好奇的眼睛。3 级只是气泡边框更粗。 |
| 喂食选菜 | 首页选“喂食”按下 → 照顾菜单第一张卡就是“喂食” → 拨轮在 6 种食物里选（小鱼、牛奶、苹果、胡萝卜、小饼干、饭团），按下喂 | 按性格的口味：最爱（三颗心 +“这是我最爱吃的”）、喜欢（两颗心）、其他（一颗心 +“谢谢你，好吃”）。没有“不喜欢”。回到首页后照旧播放吃饭的爱心动画和“好吃”台词。 |
| 洗澡 | 照顾菜单“洗澡” → 轻轻摇 3 次搓出泡泡 → 把团团扣过来冲水 | 泡泡一个个出现；冲完说“洗得香香的” |
| 梳毛 | 照顾菜单“梳毛” → 拨轮**来回**转 6 下 | 每来回一次一个进度点；一直往一个方向转不算 |
| 挠痒 | 照顾菜单“挠痒” → 轻摇 3 次 | “哈哈哈，好痒呀！” |
| 哄睡 | 睡前仪式的最后一步（日记之后） | 扣过来，或放下静置 3 秒 → 团团睡着，接着进入原有睡觉流程；没人动 60 秒也会去睡 |
| 装扮 | 照顾菜单“装扮” → 拨轮在**已解锁**的物品间选，按下穿上，再按一次脱下，长按离开 | 首页团团戴着/穿着，小床和小灯出现在首页两侧 |
| 好习惯打卡 | 家长先在家长菜单第 2 页选一个习惯；孩子在照顾菜单“打卡”按下打勾 | 当天只能打一次；连续 3 / 7 / 14 天各得一张贴纸 |
| 贴纸本 | “玩”菜单最后一张卡 → 拨轮翻页（每页 6 张），按下或长按离开 | 已得到的是带图案的圆章，没得到的是虚线圈加问号 |
| 团团日记 | 傍晚/夜里在首页选“睡觉”：先收玩具（按 3 下把 3 个玩具放进箱子），再看日记，最后哄睡 | 团团按性格念：开头 → 今天吃了什么 → 读了绘本 → 玩了游戏 → 照顾了几次 → 完成的好习惯 → 晚安。什么都没发生时说“今天我们安安静静的，也很好”。按一下（或 45 秒后）进入哄睡 |
| 早安仪式 | RTC 定时开机（原有 V3-04 早安） | 原有早安句之后接：房间冷/热/舒服、今天的节日话术、今天的好习惯提醒 |
| 节日 | 不用操作 | 新年（戴派对帽）、春节初一到初三、元宵、儿童节、端午、中秋、孩子生日：首页左侧出现灯笼/气球/粽子/月饼/蛋糕，早安说节日话术，第一次见到节日或生日各得一张贴纸 |

照顾菜单（6 张卡）：喂食、洗澡、梳毛、挠痒、装扮、打卡。“玩”菜单在原来 5 个游戏后多了“贴纸本”。

安静时段、低电量、语音进行中：照顾菜单和游戏一样被拒绝，首页“喂食”退回原来的直接喂食（不惩罚，照样有爱心）。
家长关闭体感时，洗澡和挠痒卡片被拒绝（记 `PET_GAME_REFUSED reason=motion_off`，停在原卡片）。

## 3. 规则（全部在 `kid_app`，主机测试覆盖）

### 3.1 时间与时钟未知
- 时间单位是“护理分钟”：本地墙钟自 1970-01-01 起的分钟数（`CareMinute`），日 = 分钟 / 1440，与 V5 记忆的 `day` 同一约定。
- RTC 不可信（未设置、早于 2025、振荡器停止）时分钟为 0：**需求全部为 0（团团心满意足），没有节日，不能打卡**（连续天数需要日期，打卡卡片按下只响提示音）；照顾和喂食照常计入总数和“今天”（未定日期的“今天”归入第一次知道日期的那天，和 V5 记忆一致）。
- 时钟倒退：不倒算需求（经过时间按 0 计），打卡拒绝。

### 3.2 需求（`CareStore::Needs`）
| 需求 | 锚点 | 每级时间 | 降低方式 |
|---|---|---|---|
| 饿 | 上次喂食 | 4 小时 | 喂食 → 0 |
| 脏 | 上次洗澡 | 12 小时 | 洗澡 → 0；梳毛降一级 |
| 无聊 | 上次玩 | 3 小时 | 挠痒、读完绘本、完成游戏 → 0 |
| 困 | 按作息相位 | 夜 3、傍晚/午睡 2、早上/白天 0 | 哄睡后 90 分钟内为 0 |

上限 3 级。从未照顾过时锚点为空 = 0 级；第一次有日期的照顾会同时启动饿/脏/无聊三个锚点（所以从没洗过澡的团团以后也会“有点脏”，但不会在第一次照顾之前）。
首页只显示最高的一个 ≥2 级的需求（并列时：饿 > 困 > 脏 > 无聊）。

### 3.3 口味（`TasteOf`）
| 性格 | 最爱 | 喜欢 |
|---|---|---|
| 好奇型 | 苹果 | 胡萝卜 |
| 温柔型 | 牛奶 | 饭团 |
| 活泼型 | 小鱼 | 小饼干 |

“常喂什么”（`MostFed`，按次数，并列取编号小的）只来自选菜的拨轮选择（`MemorySource::DialChoice`）。

### 3.4 贴纸（每个里程碑一张，id = 位号，只追加）
| id | 名称 | 条件 | id | 名称 | 条件 |
|---|---|---|---|---|---|
| 0 | first_book | 读完第 1 本（V5 里程碑） | 10 | first_brush | 第 1 次梳毛 |
| 1 | five_books | 5 本 | 11 | first_tickle | 第 1 次挠痒 |
| 2 | ten_books | 10 本 | 12 | first_lull | 第 1 次哄睡 |
| 3 | first_game | 完成第 1 个游戏 | 13 | habit_3 | 习惯连续 3 天（取历史最好） |
| 4 | ten_games | 10 个游戏 | 14 | habit_7 | 连续 7 天 |
| 5 | first_like | 第 1 次选择喜好 | 15 | habit_14 | 连续 14 天 |
| 6 | seven_days | 7 个活跃日 | 16 | birthday | 设备在孩子生日当天开机 |
| 7 | first_feed | 选菜喂第 1 次 | 17 | festival | 设备第一次遇到节日 |
| 8 | ten_feeds | 选菜喂 10 次 | 18 | care_star | 照顾总数 20 次 |
| 9 | first_bath | 第 1 次洗澡 | | | |

贴纸一旦得到就不会失去（只有家长“清除记忆”会清空，和 V5 成长一致）。每次账本提交（宠物动作、记忆事件、照顾事件）都在**同一次提交**里重新评估。

### 3.5 装扮和小屋（12 件，全部由贴纸解锁）
| 部位 | 物品（id） | 解锁贴纸 |
|---|---|---|
| 头 | 帽子(1)、蝴蝶结(2)、皇冠(3)、小花(4) | first_feed、first_bath、ten_books、first_like |
| 脖子 | 围巾(1)、领结(2)、奖牌(3) | first_brush、first_game、seven_days |
| 脸 | 眼镜(1)、墨镜(2) | first_book、ten_games |
| 小床 | 小床(1) | first_lull |
| 小灯 | 台灯(1)、星星夜灯(2) | five_books、habit_7 |

只能穿已解锁的（存储解码也会拒绝“穿着未解锁物品”的数据）。新年当天头上换成派对帽（不改存储的装扮）。

### 3.6 好习惯
预设 8 个：刷牙、洗手、收玩具、喝水、自己穿衣服、吃蔬菜、按时睡觉、看书。家长在家长菜单第 2 页选（0 = 不设）。
- 一天只能打一次勾；前一天打过则连续 +1，否则悄悄从 1 重新开始（不提示断签，历史最好和总天数保留）。
- 换一个习惯 = 新的记录（连续/最好/总数清零，已得贴纸保留）。
- 来源：孩子的拨轮/按键（`DialChoice`/`Button`）；语音、网络不能打卡。

### 3.7 节日（`FestivalOn`）
公历：元旦 1/1、儿童节 6/1。农历：春节（初一到初三）、元宵（正月十五 = 春节 + 14 天）、端午、中秋，用内置表覆盖 **2024–2035**（`care_calendar.cc`，已用 `lunardate` 核对）。表外年份不猜农历节日。生日（只存月/日，2 月可设 29 日，平年在 2 月 28 日过）优先于其他节日。

### 3.8 日记与早安（`ComposeDiary` / `ComposeMorning`）
只用账本数据：照顾“今天”（最后吃的食物、照顾次数、是否打卡）+ V5 记忆“今天”（读书数、游戏数）；日期不是今天的数据算空。开头和结尾三种性格各一句，其他句子共用。早安的“冷热”用状态栏温度（≥28 ℃ 热，≤16 ℃ 冷，否则舒服）；板子目前不读湿度，所以“干/湿”两句暂不触发（规则已实现）。

### 3.9 守卫（ADR-012、V5-03）
| 事件 | 允许来源 |
|---|---|
| 喂食选菜 `Fed`、装扮 `Dressed` | 仅 `DialChoice` |
| 洗澡/梳毛/挠痒/哄睡、节日 `FestivalSeen` | 仅 `Device`（设备上的会话规则） |
| 打卡 `HabitDone` | `DialChoice`、`Button` |
| 设习惯 `HabitSet`、设生日 `BirthdaySet` | 仅 `Parent` |
| 任何照顾/成长/贴纸 | **`Voice`、`Network` 一律拒绝**，且不消耗事件 id、不写 NVS |

会话本身不写存储：结束时交出一个事件，由账本校验。用力摇只给“轻一点点哦”，从不推进进度；平放静置不会被当成摇动（测试里几百个静置窗口不推进洗澡/挠痒）。

## 4. 存储格式

### 4.1 账本 schema v4（`pet_atomic_ledger`）
v4 = v3 + 96 字节 `CareStore`，追加在 CRC 之前：v1 1480 B、v2 1768 B、v3 1796 B、**v4 1892 B**。
- 读取：v1–v3 仍能加载（照顾数据为空），下一次提交把 v4 写到另一个槽位，旧槽位保留作回滚；长度与版本号不符、照顾段不规范都按损坏处理（另一个槽有效时用另一个）。
- 迁移测试：`tests/fixtures/ledger/v3_pre_v8.bin` 是**用改动前的代码真实写出的 v3 blob**（含喂食、读书、喜好、家长设置），`test_care_ledger` 验证它原样加载、事件 id 去重窗口保留、第一次照顾提交后升级为 v4 且 v3 槽不变。
- NVS：每个槽从 59 个条目变为 62 个（两个槽共 +6 个条目，约 192 字节）。
- `RecordCare` 与宠物/记忆事件共用 128 个 id 的去重窗口；被拒绝的事件不占用 id。家长“清除记忆”同时清空照顾数据（保留生日和习惯预设）。
- 家长设置**没有**改 `ParentSettingsCodec`：习惯和生日存在 `CareStore`，通过 `Parent` 来源的照顾事件写入。

### 4.2 `CareStore` 布局（小端，96 字节，保留字节必须为 0）
```
0 format=1  1 habit  2 生日月  3 生日日  4..8 各部位穿戴物品(头/颈/脸/床/灯)  9..11 0
12 fed_at  16 rested_at  20 bathed_at  24 played_at   (u32 护理分钟，0 = 无)
28 6 种食物次数 (u16)  40 贴纸位图 u32
44 连续天数  46 最好  48 总天数 (u16)  50 0  52 最后打卡日 u32
56 总计：喂食/洗澡/梳毛/挠痒/哄睡 (u16)  66..67 0
68 今天日期 u32  72 今天吃过的食物位图  73 最后的食物  74..78 今天各项次数  79 今天已打卡
80..95 0
```
所有计数饱和（今天 ≤250，总数 ≤65535），解码严格（未知贴纸位、未解锁却穿着、连续>最好>总数、食物位图与最后食物不一致、日期矛盾、保留字节非 0 都拒绝，并要求重新编码后逐字节相同）。

### 4.3 状态快照（服务器 S2）
只追加：`"ledger_schema"` 由 3 变 4（含义不变：账本版本），JSON 末尾追加 `"stickers":[0,7,17]`（已得贴纸 id，升序）。
服务器（`services/pet_learning/sync.py`）：接受账本 3 和 4；`stickers` 当且仅当 v4 出现，必须升序不重复、0–31；作为账本内容参与同代哈希；随记忆投影保存（清除记忆墓碑期间不投影）；`GET /v1/parent/devices/{id}/memories` 的 `memory.stickers` 给出 `[{id, name}]`（未知 id 的 name 为 null）。金样 `tests/fixtures/sync/snapshot_*.json` 已同步重生成（C++ 与 Python 两侧一致）。

## 5. 活动列表（给其他会话的共享入口）

首页“玩”（拨轮选 Game 项按下）打开的游戏菜单，以及 V8 新增的“照顾”菜单，卡片都来自
同一张数据表：`firmware/components/kid_app/include/kid_app/activity_list.h` 的
`kActivities[]`。`GameMenu`（`motion_game.h`）按分组（`ActivityGroup::Play` /
`ActivityGroup::Care`）读这张表，一次显示 3 张卡片，窗口随高亮滑动，按下返回该行的
`GameChoice`。这一部分是独立提交（PR #102）。

### 追加一个活动（3 步）

1. **追加 id**：在 `enum class GameChoice` 末尾追加一个值（从 13 起，已占用 1–12）。
   只追加，不改号、不复用。建议分段：会话② 13–19、会话③ 20–26、会话④ 27–33。
2. **追加一行**：在 `kActivities[]` 里对应分组的“append ... rows above this line”注释
   上方加一行 `{GameChoice::Xxx, ActivityGroup::Play, 图片id, ActivityNeeds::..., "xxx"}`。
   - 图片必须是 `SceneComposer` 已经会画的 id（`GameArt` / `MicArt` / `CareArt`）；
     新图片先追加到对应枚举并在 `scene_model.cc` 的卡片绘制里实现。
   - `needs`：`Motion`（家长关掉体感时板子会拒绝）、`Mic`、`None`。
   - 编译期 `static_assert(ActivityTableValid())` 检查 id 唯一、图片已知、每组至少 3 张。
3. **追加分派**：在 `scripts/p1_integrate.py` 的 `HandleMenuOutput()` 里，在
   “V8 activity list ... add their dispatch branch here” 注释处加一个
   `else if (out.chosen == kid_app::GameChoice::Xxx) { ... }` 分支。
   没有分派分支的行被按下时，板子记 `PET_GAME_REFUSED reason=no_handler` 并留在菜单里，
   不会误启动别的游戏。

表是头文件内 `constexpr`，追加行**不需要**改任何编译脚本。卡片顺序就是表的顺序；
`ActivityIndexOf(id)` 给出某个 id 在本组里的卡片下标（用于被拒绝后重新打开菜单停在原卡片）。
注意 V8 在 Play 组末尾加了“贴纸本”，所以 Play 组现在有 6 张卡；其他会话的新行加在“贴纸本”之后。

主机测试：`tests/cpp/test_motion_game.cc` 的 `TestActivityList()` 会遍历 Play 和 Care 组的每一行，
确认菜单能选到、按下返回的 id 正确。追加行后这个测试自动覆盖新行。

`SceneKind` 由会话①新增 `Care`(5)，用于照顾、日记、贴纸本画面；其他会话请继续用 Game / Reader。
